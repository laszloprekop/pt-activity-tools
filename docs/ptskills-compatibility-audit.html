PTSkills Compatibility Audit

Why the 14 Packet Tracer lab files of the course do not grade correctly in newer Packet Tracer versions, what was fixed, and which version and which files to use.

Course Z0025E Computer Networks, Labs 2 to 6 · checked on 1 and 2 October 2026 · Packet Tracer 7.2.2, 8.0.0, 8.2.2 and 9.0.1

Words used on this page

Activity
One .pka file. It holds a network to work on, the lab instructions, and a hidden list of checks.
Check
One thing Packet Tracer looks at when you press Check Results, for example "PC 1B has IP address 172.16.1.2". Packet Tracer calls these assessment items.
Expected value
The answer stored inside the file for a check. Your work is compared with it.
Original file
The file as shared on Canvas. All 14 were saved by Packet Tracer 4.1 in 2007.
Fixed file
The same activity with its broken checks repaired, still in the original file format. Its name ends in _fixed. This is the file to use.
Converted file
An alternative repaired copy, re-saved in the Packet Tracer 8.0 format. Its name ends in _v8. It does not open in Packet Tracer 7.x.
Solved copy
A test copy in which the network is already finished. Every check should pass; if one does not, the file is broken, not the student.

In short

  • All 14 lab files on Canvas are from Packet Tracer 4.1. Every newer Packet Tracer has to translate them when it opens them, and the translation loses information.
  • In Packet Tracer 9.0.1, the version students download today, and equally in 8.2.2, 12 of the 14 files can never be completed. Two of them (PTSkills 1 and 8) stay at 0 % no matter what you do.
  • In Packet Tracer 7.2.2 and 8.0.0 the files grade, but two routing activities (PTSkills 13 and 14) silently lose nine checks each, and the 8.0.0 guest mode limits saving.
  • The 14 fixed files (_fixed) repair this. In 7.2.2, 8.2.2 and 9.0.1 they start at 0 % and reach 100 % when the work is correct, and they keep all their checks. The instructions inside are unchanged.
  • Recommendation: use the newest Packet Tracer (9.x) together with the fixed files. The fixed files also work if you have an older version.

Which Packet Tracer version to use

Four versions were available for testing: 7.2.2, 8.0.0, 8.2.2 and 9.0.1. All four were run by script.

What each version brings, from Cisco's release notes and from the test runs on this Mac. "Observed" means it was seen in the runs; the rest is from the notes.

9.x (9.0.1 tested) Recommended

Benefits
  • The current version, the one Cisco ships and supports today.
  • Guest login works again (observed), so no Cisco account is needed to start.
  • Accessibility work: screen-reader support, keyboard focus and navigation. 9.0.1 adds security and stability fixes on top of 9.0.0.
  • Big feature release for industrial networking: new industrial routers and switches, an industrial firewall, a C8200 router, PLCs and 11 industrial protocols. Not needed for these labs, but it is where new course material goes.
  • With the fixed files every activity grades correctly (observed).
Drawbacks
  • With the original files 12 of 14 activities cannot be completed (observed).
  • Counts the activity's built-in ping tests as extra items, so the counter can show 57/55. Harmless.
  • Larger download and slower start than 8.0.

8.2.2 Verified

Benefits
  • The bug-fix end of the 8.x line. 8.2.2 (June 2024) fixed crashes caused by conflicting Windows libraries and a set of accessibility, usability and security bugs; message boxes were reworded.
  • 8.2 added an ASA 5506-X firewall, IoT boards with wired and wireless connectivity, an IoT home gateway, the show ip ospf interface brief commands, proxy settings in the login window and auto-focus on the CLI tab.
  • 8.1 added Tutored Activities (.pksz files with hints) and Windows 11 support.
Drawbacks
  • No guest mode: the guest login was removed in 8.0.1, so a Cisco Networking Academy or Skills For All account is required, otherwise the program quits (observed).
  • Grades exactly like 9.0.1 (observed): the original files fail the same checks, and all fixed files pass.

8.0.0 Usable

Benefits
  • Translates the original files well: 12 of 14 grade fully even without conversion (observed).
  • Small and fast.
  • Has a guest login (observed).
Drawbacks
  • Guest mode has a session timer and allows only three saves per session, so you can lose work (observed).
  • Drops nine checks in PTSkills 13 and nine in PTSkills 14 with the original files (observed).
  • Mac users reported bugs that later versions fixed: modules that cannot be dragged into device slots, keyboard input problems in the CLI, a library error when run as a standard user.
  • Old version, no longer offered for download.

7.2.2 Usable

Benefits
  • Grades the original files like 8.0.0: 12 of 14 grade fully even without a fix (observed).
  • Has a guest login (observed).
  • Opens the fixed files and grades all 14 fully (observed).
Drawbacks
  • Cannot open the _v8 files at all: they are saved by 8.0.0, and older Packet Tracer cannot read newer files. It shows an empty workspace without an error (observed).
  • Drops the nine OSPF checks in PTSkills 13 and 14 with the original files (observed).
  • Old (2019), Intel-only on Mac (runs through Rosetta), asks on every start whether to enable the "PT INTERNAL" script module.

For these labs none of the newer devices or protocols matter: the activities use 1841 routers, 2960 switches, PCs and one server, which every version has. The practical differences are the login, the stability fixes, and the grading engine, and the fixed files make the grading engine behave the same in every version.

Bottom line: whichever version you install, use the fixed _fixed files. They are the only files that were shown to grade correctly in every tested version, from 7.2.2 to 9.0.1. The original files are only safe in 7.2.2 and 8.0.0, and even there two activities lose checks.

What a fixed file is

A fixed file is the original activity with a small set of corrections written straight into it by a script (pka-fix), saved under a new name. No Packet Tracer is involved, and the file stays in the original 2007 format.

  1. Missing expected values are filled in. For the cable checks (which port, which cable type) and the PC's DNS server, the script reads the right answer from the activity's own answer network and stores it, the same value Packet Tracer 8.0.0 would compute.
  2. Old value formats are rewritten. A few checks (FastEthernet duplex and bandwidth, OSPF passive interfaces) stored their answer in a 2007 format; the script writes the modern one.
  3. The OSPF checks get the ID modern Packet Tracer expects. The 2007 files name OSPF networks with a subnet mask, current versions with a wildcard mask. With the corrected ID every version keeps the nine OSPF checks of PTSkills 13 and 14.

What stays exactly the same:

  • The instructions and the lab sheet shown in the activity window.
  • The starting network, the answer network, device names, addresses and cables.
  • The number of checks and their point values.
  • The file format, so every version from 7.2 up opens it.

What is different:

  • Every check has a usable expected value, which is what 8.2 and 9.x need.
  • The file name ends in _fixed so it cannot be confused with the original.
  • PTSkills5 needed no fix; its fixed file is the original under the new name, so the set is complete.

The fixing script was contributed to the repository by a fellow student (pull request 1) for people who cannot run Packet Tracer 8.0.0. An earlier route, letting Packet Tracer 8.0.0 re-save each file and then repairing what it drops, produced the _v8 set; it gives the same grading in 8.x and 9.x but a file 7.x cannot open.

What is wrong with the original files

Error 1: missing expected values (breaks 9.x)

In the 2007 files, some checks have no expected value stored. These are the checks for cables ("which port is this cable connected to" and "is it a straight-through or crossover cable"), the DNS server address on a PC, and port duplex settings. Packet Tracer 8.0.0 works out the missing values from the answer network when it opens the file. Packet Tracer 9.0.1 does not; it compares your work with the empty value, and empty never matches. The result is a check that is always "Incorrect".

Since which version?

  • Known good: 7.2.2 (2019) and 8.0.0 (January 2021). Both recompute the missing expected values when they open an old file (measured on all 14 files).
  • Known broken: 8.2.2 (June 2024) and 9.0.1 (2025). Both compare against the stored, empty value. 8.2.2 fails exactly the same items as 9.0.1 (verified on all 14 files).
  • Not testable here: 8.0.1, 8.1.0, 8.2.0 and 8.2.1. The change happened in one of these. The most likely candidate is 8.1.0 (November 2021), which introduced a new activity engine for Tutored Activities and reworked the assessment feedback; that is an educated guess, not a measurement.
  • Versions 5.x to 7.1 were not run here. By reasoning: empty expected values were normal in 4.1 files, because 4.1 compared the student's network with the answer network directly, and 7.2.2 and 8.0.0 still work that way. So Error 1 most likely appeared only after 8.0, and the files graded correctly from 5.x through 8.0.
  • Error 2 is much older, and now dated from files. Activity files that other people published on GitHub carry the version that saved them and their own grading tree, so they show how each generation named route checks:
    • 6.0.1 (2013): static routes are already named "Route0, Route1" with the modern value format, exactly as today. The 2007 naming ("0.0.0.0/0: 10.10.10.6(0)") was therefore dropped between 4.1 and 6.0.1, that is in 5.x or 6.0. OSPF networks very likely changed in the same rework; no 5.x or 6.x file with OSPF checks was found to prove it directly.
    • 7.1.1 (2017): EIGRP networks are "Route0" with a wildcard mask, no spare copies yet.
    • 7.2.0 (2018): a Cisco Community bug report says static-route checks stopped matching after a file was saved and reopened. 7.2.2 files are the first with the "(deprecated) Route0" spare copies next to every route check, which is the compatibility fix. 8.0.0 still builds those spare copies for static routes, RIP and OSPF networks, and that is where 8.0.0 attaches the 2007 static-route and RIP checks. The OSPF checks match neither copy, because their 2007 names carry a subnet mask and an "area0" suffix.
    So PTSkills 13 and 14 have most likely lacked their nine OSPF checks since Packet Tracer 5.x or 6.0, more than a decade before 8.0. Measured: 7.2.2 already loses them (80 of 89 and 46 of 55 kept).
  • Side note for teachers: in 7.3.1 and later, OSPF (and other technologies) are hidden from the Activity Wizard's answer tree by default and must be enabled under Options, Preferences, Answer Tree. This affects authoring new activities, not these files.

Error 2: routing checks are lost in translation (all versions)

Newer Packet Tracer names route-like checks differently. A static route that was called "0.0.0.0/0: 10.10.10.6(0)" is now "Route0", and OSPF networks changed from a subnet mask to a wildcard mask. When a version opens an old file it tries to match the checks by name:

  • Static routes and RIP networks are kept, but attached to a spare "deprecated" copy of the check.
  • OSPF networks are not matched at all. PTSkills 13 and 14 each lose nine checks, in 7.2.2, 8.0.0, 8.2.2 and 9.0.1.

Error 3: the file format itself

Every file is still in the 2007 format. Each time it is opened, Packet Tracer translates it again, and that translation is where errors 1 and 2 happen. The fixed files stay in this format on purpose, so that 7.x can still open them; the corrections inside make the translation come out right in every version.

Not an error

The PC network port was renamed from "FastEthernet" to "FastEthernet0" over the years. Both 8.0.0 and 9.0.1 handle that rename correctly. An earlier guess that this caused the stuck scores was wrong.

What this means for a student

The lab reports require a screenshot of Check Results, so every check that cannot pass costs the student directly.

  • Stuck scores with no useful feedback. The student re-checks cables, port names and addresses that are already right. The teacher's advice ("redo the cabling") cannot help, because the comparison is against an empty value.
  • Impossible deliverables. On 9.0.1 a 100 % screenshot cannot exist for PTSkills 1, 2, 3, 4, 6, 7, 8, 9, 10, 11 and 12.
  • Wrong lessons. PTSkills8 teaches straight-through versus crossover cables. On 9.0.1 the correct crossover cable between server and router is marked Incorrect, which teaches the opposite of the lesson.
  • Lost work on 8.0.0. Students who switch to 8.0.0 to escape the problem meet the guest timer and the three-save limit.
  • Fewer checks than the lab sheet lists. In PTSkills 13 and 14 the OSPF checks are missing, so the file no longer matches the teacher's rubric.

What was fixed

  1. Expected values filled in from each activity's answer network: 2 checks in PTSkills1, 3 in 2, 5 in 3, 5 in 4, 16 in 6, 6 in 7, 20 in 8, 14 in 9, 44 in 10, 7 in 11, 16 in 12. These are exactly the checks that could never pass in 9.0.1.
  2. Old formats rewritten: 10 checks in PTSkills9 (duplex and bandwidth), 9 OSPF networks in PTSkills13, 9 OSPF networks and 3 passive interfaces in PTSkills14.
  3. Nothing else touched: the script reports 0 unknown checks and 0 warnings on all 14 files.

Deliberately left unchanged: the instruction text, the device names, addresses and cabling, the point values, the file format, and the file names apart from the _fixed ending.
